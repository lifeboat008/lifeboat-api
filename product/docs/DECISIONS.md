# Lifeboat decisions

| ID | Decision | Reason | Revisit when |
| --- | --- | --- | --- |
| LB-001 | Go is the backend language across the four repositories. | Shared domain types and reliable service tooling. | Another language has proven integration demand. |
| LB-002 | GitHub activity is evidence, not payment approval. | A merged change can still be out of scope or disputed. | Never for automatic payment in the MVP. |
| LB-003 | A human steward opens a rescue task. | Inactivity alone does not prove abandonment or transfer rights. | Better governance is designed with maintainers. |
| LB-004 | Begin with Stellar testnet. | Money flow and retry logic need validation before mainnet. | Pilot controls are complete. |
| LB-005 | No Soroban lockup in the MVP. | The initial workflow can use approved Stellar payments. | A concrete trust requirement warrants a contract. |
| LB-006 | Mainnet custody and payout asset remain open. | These choices affect legal and operational design. | Before accepting real funds. |
